# Contract — `holdout` program instructions

**Phase 1 output of `/speckit-plan`.** The on-chain interface the Kotlin app, the Kotlin crank and the TypeScript tests all target. Account layouts: `data-model.md` §1. State machines: spec §8. Every guard below is enforced by the program, never only by a client.

Conventions: `now` = Clock sysvar `unix_timestamp`. "Anyone" = any signer paying the fee; the caller's identity never changes the outcome (FR-030a). **[Phase 2]** marks items built only after Phase 1 is complete (spec §3a).

---

## 1. Privileged instructions

| Instruction | Signer | Args | Guards | Effects |
|---|---|---|---|---|
| `initialize` | the program's **upgrade authority** | `operator`, `sponsor`, `treasury_wallet`, `developer_wallet` (H35), `faucet_sol_top_up`, `faucet_daily_lamport_cap`, `faucet_sponsor_float` | `Config` does not exist; the signer **is the program's current upgrade authority**, read from the program's `ProgramData` account (passed as an account, seeds-derived), else `NotUpgradeAuthority` (6003). Before `Config` exists there is nothing else to authenticate a signer against, so without this guard any stranger could initialize the freshly deployed program first, keep `admin`, and set `operator`, `sponsor` and the fee destination to their own addresses — leaving no way to reclaim the program ID (R14) | Creates `Config` with `admin = signer` and `chip_set` zeroed, `version = 0`, `max_top_tier = 0`; creates the mock SKR mint with mint authority `["mint_authority"]`; creates `fee_destination` (the treasury's SKR token account — **operations**) and `developer_destination` (the developer's — H35); creates the faucet vault. Flags start `false` |
| `create_league` | admin | `league_id`, `duration_days`, `reps_per_day`, `exercise`, `form` (H35), `first_start`, `day_length`, `cadence`, `join_lock` | `exercise == 0` (push-ups); `1` and `2` are reserved for later exercises and rejected here (H30). `form` is 0 (from the toes, Hard) or 1 (knees allowed, Easy) — and fixed for the judged leagues: league 0 (7-day) only 1, league 1 (21-day) only 0; a test league takes either — else `InvalidForm` (6013). | `set_flags` | admin | `genesis_gate_enabled` | — | Updates the flag; emits `FlagsSet { genesis_gate_enabled }`. There is no ladder gate (FR-003) |
| `publish_chip_set` | operator | `amounts: [u64; 4]`, `valid_until: i64` | `0 < a0 < a1 < a2 < a3`; `now < valid_until`, else `ChipSetExpired` (6014) — a set that outlived its send never lands after the deadline the Operator signed: the publish window's close for the weekly publish, chain time + 10 minutes by default for a hand publish (FR-055a, FR-056). ## 2. Permissionless automation

| Instruction | Accounts (beyond signer, programs) | Guards | Effects |
|---|---|---|---|
| `open_cohort(league_id, index)` | `LeagueConfig`, new `Cohort`, new vault, previous `Cohort` (if `index > 0`), `Config` | `index == next_index`; if `index > 0`, `now ≥ previous.start`; `Config.chip_set.version > 0`, else `ChipSetNotPublished` (6012) — a cohort opened before the first chip set is published would copy four zeroed amounts and keep them for its whole life (FR-007, FR-055), accepting zero-stake joins that no later publish can correct | Creates `Cohort` with `start = first_start + index × cadence`, `join_cutoff = start − join_lock`, league parameters — `duration_days`, `reps_per_day`, `day_length`, `exercise` — and `Config.chip_set.amounts` copied; `next_index += 1`; emits `CohortOpened`. **[Phase 2]** also delivers any held carry-over of this league into the new cohort |
| `record_forfeits` | `Cohort`, vault, `fee_destination` (operations), `developer_destination`, `Config`; remaining accounts = up to 10 `(Membership, Profile)` pairs | Each pair: membership belongs to cohort, profile matches membership wallet | For each pair where `state == Joined ∧ in_breach(now)`: split the stake 70 / 10 / 10 / 10 (FR-027, H35; re-split 2026-10-12): `pool += pool part`, `comeback_due += pledge` (the member's 10 % pledge stays in the vault until `settle_count` counts the forfeit, FR-037c), and page-batched transfers of the developer parts → developer destination and the operations parts → fee destination; `held_stake −= stake`; `state = Forfeited`; `forfeits_recorded += 1`; profile: `forfeited += 1`, `last_changed = max(last_changed, deadline_of(days_completed))` — **the deadline they missed, never `now`**: the instant is derived from the outcome, so neither the page order nor how late the crank runs can reorder two tied members on a leaderboard (FR-060b), and the `max` keeps a late-recorded older outcome from moving it backwards — clear `running` if it is this cohort — **the league streak is not touched here**, because a mid-cohort forfeit can be recorded before an earlier cohort of the same league has been counted (FR-061a); emit `ForfeitRecorded`. Pairs not in breach, or already forfeited, are skipped without error (idempotent, any order) |
| `settle_count` | `Cohort`, vault, `fee_destination`, `developer_destination`, `Config`, `LeagueConfig` (**mut**, 2026-10-12), the league's **reserve vault** (**mut**, 2026-10-12), the league's cohort `index − 1` (only when `index > 0`); remaining accounts = up to 10 `(Membership, Profile)` pairs | **Each pair: `membership.cohort == cohort` and the profile is the one the membership's wallet derives, both checked before any mutation — a pair from another cohort fails the whole page with `AccountMismatch` (6060), exactly as `record_forfeits` requires. Without it a caller could count a foreign membership, mark it `counted`, and drive this cohort's `counted` to `member_count` without its own members ever being counted.** `status == Settling` (`now ≥ end ∧ !settled`); when `index > 0`, the previous cohort of this league is `settled` — counting runs in cohort order so every profile's streak does too (FR-061a, INV-9) | For each pair with `counted == false`: if `Joined ∧ in_breach` → forfeit exactly as `record_forfeits`; then if `Joined ∧ days_completed == duration_days` → `state = Finished`, `finisher_count += 1`, `finishers_per_tier[tier] += 1`, `total_finisher_stake += stake`, profile `cleared += 1`, clear `running`. **This is the only step that writes a streak:** `current_streak += 1` and `longest_streak = max` for a finisher, `current_streak = 0` for a membership counted in any forfeited state — whenever it was recorded — and `last_changed = max(last_changed, t)` either way, where `t` is the outcome's own instant: the cohort's `end` for a finisher (identical for everyone who cleared it, FR-031) and the missed `deadline_of(days_completed)` for a forfeit. Never `now`, so the crank's timing cannot rank one tied member above another (FR-060b). **These profile figures land page by page**, so a cohort mid-count has some of its members' figures written and not others; leaderboards therefore read a league only as of its last `settled` cohort (FR-060a), and FR-061a bounds this to one cohort per league at a time. Set `counted = true`, `cohort.counted += 1`; emit `MemberCounted`. Already-counted pairs are skipped **H35, rewritten 2026-10-12 (FR-037c–e):** an unrecorded breach is split as in `record_forfeits`. **Counting a forfeit** moves its pledge `floor(10% × stake)` vault → the league's reserve vault (one transfer per page) and `cohort.comeback_due −= pledge`; then, with the member's progress slot `p` for this league: (a) if `p` is empty or holds a pledge of **this** league, any old pledge is released (`league.comeback_reserve −= old`, `league.boost_reserve += old`), then `league.comeback_reserve += pledge` and `p` opens the new comeback — `comeback_stake = stake`, `comeback_league = league_id`, `comeback_round = first`, the smallest index with `first_start + first × cadence > missed_deadline`, and `comeback_last_round = last`, where `last = first` if `first_start + first × cadence − join_lock > missed_deadline + 1` (the round is still open to join the second after the miss) and `last = first + 1` otherwise — a miss on a round's last day (a later forfeit replaces the earlier one; counting runs in cohort order, so "later" never depends on the crank); (b) **test builds only:** if `p` holds an open pledge of **another** league (every test league shares one slot), nothing opens: the new pledge goes to `league.boost_reserve` and `p` is left alone. **Counting a finisher** whose slot holds an open pledge of this league: if `comeback_round ≤ cohort.index ≤ comeback_last_round` (the first one finished uses it), `membership.comeback_entitled = min(floor(10% × comeback_stake), stake)`, `cohort.comeback_owed += entitled`, the excess `pledge − entitled` is released (`comeback_reserve −= excess`, `boost_reserve += excess`) and `p` is closed (`comeback_stake = 0`); if `cohort.index > comeback_last_round`, the whole pledge is released and `p` closed; if `cohort.index < comeback_round`, nothing changes. A pledge of another league in the shared test slot is never touched by a finish. No token moves for a release: both reserves live in the one reserve vault |
| `settle_finalize` | `Cohort`, vault, `fee_destination` (operations: the rounding remainder), `LeagueConfig` (writable), the league's reserve vault, the league's cohort `index − 1` (only when `index > 0`) — **no `developer_destination` since 2026-10-12** | `status == Settling`; `counted == member_count`; for `index > 0`, the previous cohort is the league's `index − 1` (`AccountMismatch`, 6060) and settled (`PreviousCohortUnsettled`, 6045) — a cohort nobody joined is never counted, so this is its own ordering check. Finalization runs in cohort order within a league (`settle_count` and `settle_finalize` both refuse cohort *i* until *i − 1* is settled), so what a cohort draws from its league's reserve depends only on earlier cohorts, never on the crank's timing (FR-037c, INV-10) | **If `total_finisher_stake > 0`, in order:** (1) `boost = min(floor(10% × pool), league.boost_reserve)` reserve → vault, `pool += boost`, `boost_received = boost`, `league.boost_reserve −= boost` (cap 10 % since 2026-10-10, was 20 %); the boost draws **only** from `boost_reserve`, never from `comeback_reserve` (FR-037d); (2) `share_per_tier[t] = floor(pool × chips[t] ÷ T)`; `rounding_remainder` → fee destination; `pool −= rounding_remainder`; (3) `comeback_funded = comeback_owed` reserve → vault and `league.comeback_reserve −= comeback_owed` — drawn in full, always: `comeback_reserve` covers every owed refund (INV-10). **If no finishers:** the whole `pool` vault → the league's reserve vault, `league.boost_reserve += pool`, `no_finisher_boost = pool`, `pool = 0` (FR-037; the developer and operations took their parts at each forfeit, and the forfeiters' pledges stay in `comeback_reserve`). **Then always:** `settled = true` (`comeback_due` is already 0: every recorded forfeit was counted); emit `CohortSettled { …, boost, comeback_funded, no_finisher_boost }` (FR-037c–e, H35; rewritten 2026-10-12) |
| `release_comeback` *(added 2026-10-12, FR-037h)* | `caller` (signer, pays the fee), `LeagueConfig` (**mut**), the member's `Profile` (**mut**; PDA derived from `profile.wallet`, which does not sign), `round`: `Option<Cohort>` — **required when `league.next_index > last`** | The profile's progress slot for this league holds an open pledge **of this league** (`comeback_stake > 0 ∧ comeback_league == league.league_id`), else `NoComebackToRelease` (6070). With `last = comeback_last_round`: if `league.next_index > last`, `round` is the league's cohort `last` (`AccountMismatch`, 6060, otherwise) and `round.settled`; else (the last round never opened) `now > first_start + last × cadence + day_length − 1` — its first day's deadline, after which not even a late join can reach it. Otherwise `ComebackStillOpen` (6071): a round can still be made good. The caller chooses no parameter, amount or recipient (FR-030a) | `pledge = floor(10% × comeback_stake)`; `league.comeback_reserve −= pledge`, `league.boost_reserve += pledge`; the slot is closed (`comeback_stake = 0`); **no token moves** (both reserves live in the one reserve vault); emit `ComebackReleased { wallet, league, round, amount }`. A second call finds no open pledge and fails `NoComebackToRelease`, so repeating it, or two schedulers at once, moves nothing twice (INV-7) |
| `top_up_sponsor` | `Config`, faucet vault, the `Config.sponsor` address (lamport recipient, does not sign) | `sponsor` lamports `< sponsor_float ÷ 2`; the refill fits `daily_lamport_cap − lamports_today` and the vault holds it | Transfers `sponsor_float − sponsor lamports` faucet vault → sponsor; adds it to `faucet.lamports_today`; emits `SponsorToppedUp { lamports }`. Anyone may call it, so a sponsor key drained by whoever extracted it from the app is restored by the next crank pass instead of ending zero-SOL onboarding (R13, FR-042b) |
| `deliver_carry_over` | *Cut 2026-10-05 (H34): nothing carries over, so there is nothing to deliver* | — | — |

## 3. Member instructions

| Instruction | Signer | Args | Guards | Effects |
|---|---|---|---|---|
| `claim_faucet` | fee payer ∈ {`Config.sponsor`, `recipient`} | `recipient: Pubkey` | `chip_set` published, else `ChipSetNotPublished` — an unpublished set mints nothing (FR-055b); **no per-wallet limit** *(removed 2026-10-12, FR-042a)*: a wallet may claim as often as it likes, every claim mints the same SKR and tops SOL up only when the recipient holds less than `sol_top_up`; `today = floor((now − 18,000) ÷ 86,400)` (days turn over at 05:00 UTC) is used only for the budget's day; **every lamport the claim takes out of the vault** — the top-up, plus the sponsor's fee and any rent it paid — must fit `daily_lamport_cap − lamports_today` and be held by the vault (R13) | Creates `Profile` and the recipient's SKR token account if missing; mints `chip_set.max_top_tier` SKR to the recipient — the largest top tier ever published, not today's, so a wallet can always stake the top chip of **any** open cohort even when a Phase 2 re-price lowered the tiers after that cohort copied them (FR-042a, FR-057); tops recipient lamports up to `sol_top_up` from the faucet vault; if the payer is the sponsor, reimburses the sponsor's fee and any rent it paid from the vault; adds every lamport that left the vault to `faucet.lamports_today` (resetting it when `lamports_day != today`); `last_faucet_day = today` (informational — nothing reads it); emit `FaucetClaimed`. Errors (not partial success) when the budget or the vault is exhausted. Only a claim that moves **no** lamports at all — the recipient pays its own fee *and* already holds `sol_top_up` — spends none of the budget. A sponsor-paid claim always charges the budget, because the fee and rent reimbursement leave the vault even when no top-up is due; that is the whole reason the cap counts lamports rather than claims (R13) |
| `join_cohort` | member | `tier: u8` | `status == Open` — **or** the comeback late join below (`status ∈ {Locked, Running}`); `tier ≤ 3`; member SKR balance ≥ `chips[tier]`; `genesis_gate_enabled ⇒` the member holds a Seeker Genesis Token, passed as **remaining accounts** `[member's Token-2022 token account, its mint]`: both owned by Token-2022, the account owned by the member and of that mint with amount ≥ 1, the mint's `TokenGroupMember.group == SEEKER_GENESIS_GROUP` — else `GenesisGateClosed`; with the flag off no remaining account is read (FR-003b, R17); after slot normalisation: `pending` is empty, and if the running cohort has not ended then `cohort.start ≥ running_cohort.end()`. The member's **running cohort is passed as an account** whenever `profile.running` is set (else `AccountMismatch`), and the end is read from it rather than from `profile.running.end`, so the rule rests on chain state alone (constitution II) and cannot be skipped by a cached end that is stale or zero. **Comeback late join (FR-037e, FR-008, FR-010; 2026-10-12):** two optional accounts, `comeback_membership` (the member's own membership in a cohort of this league) and `comeback_cohort` (its cohort), with the league's `LeagueConfig` for the schedule. They are accepted when the membership is the member's and is `Forfeited` or (`Joined` ∧ `in_breach(now)`), its missed deadline is `m = deadline_of(days_completed)` of `comeback_cohort`, the target is the league's `first` for `m` — `target.start > m ∧ target.start − cadence ≤ m` — and the target is closed to everyone else (`m + 1 ≥ target.join_cutoff`; otherwise the join is the plain open one); then the target may be `Locked` or `Running` as long as `now ≤ target.start + day_length − 1` (its first day's deadline). Without the accounts, or outside that window, joining a closed cohort fails `JoiningClosed` (6021). The remaining guards apply unchanged | Creates `Profile` if missing and `Membership` (member pays rent); transfers `chips[tier]` member → vault; `held_stake += stake`, `member_count += 1`; `profile.pending = {cohort, start, end}`; emit `MemberJoined`. A late join into a `Running` cohort (`target.start ≤ now`) is normalised at once: `pending` moves into `running` in the same instruction; `member_count` rises after the start, so `member_count_at_start` (data-model §5) can rise until the first day's deadline |
| `leave_cohort` | member | — | `status == Open`; membership `state == Joined` | Transfers `stake` vault → member; `held_stake −= stake`, `member_count −= 1`; clears `profile.pending`; **closes** `Membership` (rent to member); emit `MemberLeft` |
| `submit_day` | member | `day_index: u8`, `proof_hash: [u8; 32]` | `status == Running`; `state == Joined`; then, **in this order**, `day_index ≥ days_completed` (6033), `day_index == days_completed` (6031), `now ≤ deadline_of(day_index)` (6032), `day_index == day_index(now)` (6031) — see §5 | `days_completed += 1`; slot normalisation; emit `DayCompleted { cohort, wallet, day_index, proof_hash }` |
| `claim_payout` | member | — | `cohort.settled`; `state == Finished` | Transfers `stake + share_per_tier[tier] + refund` vault → member, where `refund = membership.comeback_entitled` **in full** (0 with no comeback; no pro-rata cut, FR-037e, rewritten 2026-10-12); `held_stake −= stake`, `pool −= share`, `comeback_claimed += refund`; `state = Claimed`; emit `PayoutClaimed { cohort, wallet, amount, comeback }` |

A second `claim_payout`, `submit_day` for the same day, `leave_cohort` after the cutoff, or `settle_finalize` on a settled cohort each fail with the errors below.

## 7. Golden fixtures (cross-language contract)

`fixtures/` is generated by the TypeScript test suite from the real program and committed:

| File | Contents | Consumed by |
|---|---|---|
| `accounts.json` | Serialized bytes + decoded fields for each account type at representative states (2026-10-12: a `LeagueProgress` with an open pledge, a `Cohort` with `comeback_due` and `no_finisher_boost`, a `LeagueConfig` with both reserves, a `Membership` with `comeback_entitled`) | Kotlin `core` decoders |
| `pdas.json` | Seed inputs → addresses | Kotlin `core` PDA helpers |
| `instructions.json` | Args → instruction data bytes and account order (2026-10-12: `settle_count`, `settle_finalize`, `release_comeback`) | Kotlin `core` instruction builders |
| `derived-figures.json` | Cohort + memberships + chain time → status, breach, survivor counter, projected pool and share, roster order, time left, and the comeback offer (the round index, the exact amount) | Kotlin `core` `Derive.kt` |
| `settlement-vectors.json` | PRD §19 V1–V22 inputs and expected outputs, plus the comeback vectors *(2026-10-12)*: the 70 / 10 / 10 / 10 split (stake 101 → 71 / 10 / 10 / 10), the comeback rounds `first` and `last` (a mid-round and a last-day miss), the late-join window, the refund and the excess released, a release, the boost never drawing from `comeback_reserve`, a no-finisher pool | Rust math tests, TypeScript integration tests, Kotlin projections |

A Kotlin test that disagrees with a fixture fails the build.
