# Contract — `crank` command-line tool

**Phase 1 output of `/speckit-plan`.** A Kotlin/JVM tool (`kotlin/crank`) built on `kotlin/core`. It is the usual caller of the permissionless instructions, the driver of scripted members, and the Operator's chip-set tool. Nothing it does is privileged except `chips publish`.

Packaging: `kotlin/crank/build/libs/crank.jar` (`java -jar crank.jar <command>`), or `./gradlew :crank:run --args="<command>"` in development.

## Configuration

| Variable | Required | Meaning |
|---|---|---|
| `HOLDOUT_RPC_URL` | yes | Devnet RPC endpoint supporting `getProgramAccounts` filters |
| `HOLDOUT_PROGRAM_ID` | yes | Deployed `holdout` program |
| `HOLDOUT_PAYER_KEYPAIR` | yes (`scripted run`: optional) | Fee payer for automation (any funded devnet wallet). `scripted run` also tops scripted wallets' SOL up from it while it stays 2 SOL above zero; without it, a wallet short of SOL is skipped that pass (2026-10-13) |
| `HOLDOUT_OPERATOR_KEYPAIR` | `chips publish` only | Must equal `Config.operator` |
| `HOLDOUT_JUPITER_API_KEY` | no | `chips publish --auto` only: a free Jupiter key sent as `x-api-key`; keyless works for a weekly call |
| `HOLDOUT_JUPITER_PRICE_URL` | no | `chips publish --auto` only: overrides `https://api.jup.ag/price/v3` |
| `HOLDOUT_ADMIN_KEYPAIR` | `init` only (or `--admin`) | Becomes `Config.admin` |
| `HOLDOUT_SCRIPTED_KEYS_DIR` | `scripted` only | Secret keypairs for the wallets listed in `scripted-wallets.json` |
| `HOLDOUT_PAGE_SIZE` | no (default 10) | `(Membership, Profile)` pairs per paged transaction |

All commands print a JSON summary to stdout and exit `0` on success, `1` on configuration errors, `2` if any transaction failed after retries. Every command accepts `--dry-run` (build and simulate, send nothing).

## Schedule

A Fly.io always-on machine (app `holdout-crank`, one machine; a trial account stops it after 5 minutes, so the account needs a card) runs `crank run && crank scripted run` **every 10 minutes**, and sooner when a cohort open falls due first: `crank run`'s summary carries `nextOpenAt` (chain time, absent when nothing falls due later) and `localTime`, and `scripts/crank-loop.sh` wakes 5 s after it on its own clock (`nextOpenAt − chainTime + localTime`), so the test lobby's next cohort opens moments after the one before starts (FR-044a). Between those passes it runs `crank scripted run` alone **only when the last one asked to**: it sleeps until `nextScriptedAt`, moved onto its own clock the same way, plus `CRANK_WAKE_MARGIN_SECONDS` (default 2), at least `CRANK_WAKE_GAP_SECONDS` (default 5) after the last run, and passes `--since` the last clean run's `chainTime`. So an open Hackathon lobby with room is checked every minute — the only timed read, the cohort list alone while the lobby is empty — and each scripted day is submitted as it opens (FR-043; owner, 2026-10-13: the devnet RPC rate-limits). A failed run is tried again within `CRANK_RETRY_SECONDS` (default 30), even when it asked for a later wake, except a configuration error (exit `1`), which waits for the next pass; and the loop exits `2` at start without `HOLDOUT_RPC_URL` or `HOLDOUT_PROGRAM_ID`. A wake starts only while `CRANK_POLL_MIN_SECONDS` (default 20) still fit before the next pass, and is stopped at that deadline, so wakes never delay a pass. The Phase 2 chip check runs hourly on the Operator's machine and publishes once a week, on its first run inside the publish window (Monday 01:00–05:00 UTC), so the cohorts opening at 05:00 lock that set. The GitHub Actions workflow `.github/workflows/crank.yml` is a disabled-by-default fallback: every 10 minutes, `crank-loop.sh --once` — one pass, then scripted wakes until `CRANK_ONCE_POLL_UNTIL`, 9.5 minutes after the job started (timeout 12 minutes); without `CRANK_ONCE_POLL_UNTIL`, `--once` wakes for `CRANK_ONCE_POLL_SECONDS` (default 0).

## Guarantees

- The crank never holds authority over stakes; losing it delays transfers and leaderboards, never outcomes (ES-8).
- Anyone can run `crank run` with their own payer and get the same on-chain result (FR-030a, acceptance criterion 5) — including the sponsor refill, which needs no key of ours.
