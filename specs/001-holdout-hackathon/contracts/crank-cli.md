# Contract — `crank` command-line tool

**Phase 1 output of `/speckit-plan`.** A Kotlin/JVM tool (`kotlin/crank`) built on `kotlin/core`. It is the usual caller of the permissionless instructions, the driver of scripted members, and the Operator's chip-set tool. Nothing it does is privileged except `chips publish`.

Packaging: `kotlin/crank/build/libs/crank.jar` (`java -jar crank.jar <command>`), or `./gradlew :crank:run --args="<command>"` in development.

## Configuration

| Variable | Required | Meaning |
|---|---|---|
| `HOLDOUT_RPC_URL` | yes | Devnet RPC endpoint supporting `getProgramAccounts` filters |
| `HOLDOUT_PROGRAM_ID` | yes | Deployed `holdout` program |
| `HOLDOUT_PAYER_KEYPAIR` | yes | Fee payer for automation (any funded devnet wallet) |
| `HOLDOUT_OPERATOR_KEYPAIR` | `chips publish` only | Must equal `Config.operator` |
| `HOLDOUT_JUPITER_API_KEY` | no | `chips publish --auto` only: a free Jupiter key sent as `x-api-key`; keyless works for a weekly call |
| `HOLDOUT_JUPITER_PRICE_URL` | no | `chips publish --auto` only: overrides `https://api.jup.ag/price/v3` |
| `HOLDOUT_ADMIN_KEYPAIR` | `init` only (or `--admin`) | Becomes `Config.admin` |
| `HOLDOUT_SCRIPTED_KEYS_DIR` | `scripted` only | Secret keypairs for the wallets listed in `scripted-wallets.json` |
| `HOLDOUT_PAGE_SIZE` | no (default 10) | `(Membership, Profile)` pairs per paged transaction |

All commands print a JSON summary to stdout and exit `0` on success, `1` on configuration errors, `2` if any transaction failed after retries. Every command accepts `--dry-run` (build and simulate, send nothing).

## Commands

| Command | Does | Safe to repeat? |
|---|---|---|
| `crank init --admin <keypair> --operator <pubkey> --sponsor <pubkey> --treasury <pubkey> --developer <pubkey> --rate <usd-per-skr> [--first-start <iso>]` | *(H35: `initialize` creates the treasury's account — the operations destination — and the developer's — the developer destination; `create_league` makes league 0 **Easy** (form 1) and league 1 **Hard** (form 0), each with its reserve vault `["reserve", id]`; a test league takes `--form easy|hard`, default easy.)* Admin helper: sends `initialize` — **`--admin` must be the keypair holding the program's upgrade authority, which the program verifies (6003)** — then `publish_chip_set` with `--rate` through `HOLDOUT_OPERATOR_KEYPAIR`, then `create_league` for the 7-day (id 0) and 21-day (id 1) leagues with devnet timing, then funds the faucet vault. Publishing before any league exists means no cohort can be opened in a window where the chip set is still zero (6012, FR-055b) | Fails harmlessly if already initialised |
| `crank run` | For each league, **in this order**: `open_cohort` if due — for test leagues, only in the newest (highest id), an older one winding down, and the newest only once every older test cohort has settled (FR-044a); `top_up_sponsor` if the sponsor holds less than half its float (FR-042b); for each running cohort: page `record_forfeits` over members currently in breach; for each settling cohort, **oldest index first**, and across leagues in the order the cohorts ended, a stuck cohort holding later ones that share its progress slot: page `settle_count` until all counted, then `settle_finalize`, which with no finishers sends the whole pool to the league's boost reserve (FR-037); then, last in the pass, **`release_comeback`** for every profile whose league progress holds an open pledge for which every round the league has opened is settled — the crank passes the cohort `min(last, next_index − 1)` once `first` is opened — and, when `last` is not opened yet, whose first day's deadline has passed by the schedule (FR-037h; the crank finds them by reading the profiles). Counting a cohort before the league's previous one has settled is refused on-chain, so the order is not a preference (FR-061a). A `release_comeback` the program refuses with `ComebackStillOpen` (6047) or `NoComebackToRelease` (6046) is skipped, not an error: another scheduler may have released it first, or its round is still open. A refill the program refuses — float still above half, or the day's lamport budget spent — is reported in the JSON summary and does **not** set exit `2`: it is an expected outcome, retried on the next pass | Yes — every step is idempotent on-chain *(H35, rewritten 2026-10-12: a forfeit pays its developer and operations parts at once and keeps the member's 10 % pledge in the cohort vault; `settle_count` moves the pledge into the league's reserve vault and opens the member's comeback; `settle_finalize` draws the boost from `boost_reserve` and the owed refunds from `comeback_reserve`; with no finishers the whole pool goes to the boost reserve; `release_comeback` sends an expired pledge to the boost reserve.)* |
| `crank scripted plan --cohort <address>` | Prints the league's floor, the cohort's current real and scripted member counts, the resulting deficit, and each scripted wallet's tier and scheduled forfeit day (seeded from the cohort address, R12) | Yes |
| `crank scripted run` | For every open cohort: fills it **only up to its league's floor** — `deficit = floor − member_count`, counting real members — with wallets that claim the faucet (SKR only) and join; half the floor when the lobby opens, the full floor 24 h before the join cutoff. For every running cohort: scripted wallets not scheduled to forfeit today submit the current day | Yes — recomputes the deficit from chain state, so it never over-fills, and skips wallets already joined or already submitted |
| `crank scripted fund --lamports <n>` | Operator tops up scripted wallets' SOL once (56 wallets × 0.02 SOL, R12) | Yes |

Floors are crank configuration — `--floor-7d` (default 20) and `--floor-21d` (default 12) — and never reach the chain: no account records which wallets are scripted, and no cohort behaves differently because of them (FR-043a, constitution I).
| `crank chips publish --rate <usd-per-skr> [--valid-until <ISO-8601 instant>]` | Converts $10/$25/$50/$100 at the given rate, rounds each down to the nearest 10 whole SKR (min 10), sends `publish_chip_set` with a deadline: chain time + 10 minutes, or `--valid-until` (refused unless after chain time); the report carries `validUntil`, and a set the program refuses as past it (6014) is reported as such | Publishes a new version each time — run deliberately |
| `crank chips publish --auto` **[Phase 2]** | The Operator's weekly re-pricing, run **every hour** by the Operator's OS scheduler in any time zone — never by `crank run`; the publish-window guard makes all but one run a week do nothing. Fetches the SKR rate from the Jupiter Price API (by mint) and publishes all four tiers re-priced at it, every week, even if unchanged; exits `0` without publishing if no rate is available, saying why; `--dry-run` reports the rate and the set it would publish | Yes — at most once per publish window, Monday 01:00 to 05:00 UTC by chain time: nothing is fetched or sent outside it or when `Config.chip_published_at` is already inside it; the report names `windowOpens`/`windowCloses`; no send starts in the window's last 90 seconds (`sendCutoff`, 04:58:30 UTC), and the chain's time is read again just before sending, so a publish never lands after 05:00 — such a run publishes nothing and reports `too late to land in the publish window`; the set is signed with the window's close as its deadline, so the program refuses one that would land after 05:00 (6014, reported as too late); every report, dry runs included, carries `insideWindow`, `alreadyPublishedThisWindow`, `sendCutoff`, `wouldPublishNow` and `validUntil`, read from the chain's time after every slow step, and a `--dry-run` still fetches, prices and simulates, so the rate source can be checked any day |
| `crank status` | Prints every cohort's status, member count, recorded forfeits, counted and settled flags; the faucet vault's balance, the sponsor's balance against `sponsor_float`, and the day's faucet spend as `lamports_today / daily_lamport_cap` — the figures the live period is monitored on (T110, FR-042b) | Yes *(H35: also both fee destinations, and per league its form, both reserves and the reserve vault's balance; 2026-10-12: the number of open pledges and how many `release_comeback` is waiting on.)* |

## Schedule

A Fly.io scheduled machine runs `crank run && crank scripted run` **every 10 minutes**, and sooner when a cohort open falls due first: `crank run`'s summary carries `nextOpenAt` (chain time, absent when nothing falls due later), and `scripts/crank-loop.sh` wakes 5 s after it, so the test lobby's next cohort opens moments after the one before starts (FR-044a). The Phase 2 chip check runs hourly on the Operator's machine and publishes once a week, on its first run inside the publish window (Monday 01:00–05:00 UTC), so the cohorts opening at 05:00 lock that set. The GitHub Actions workflow `.github/workflows/crank.yml` is a disabled-by-default fallback with the same commands.

## Guarantees

- The crank never holds authority over stakes; losing it delays transfers and leaderboards, never outcomes (ES-8).
- Anyone can run `crank run` with their own payer and get the same on-chain result (FR-030a, acceptance criterion 5) — including the sponsor refill, which needs no key of ours.
